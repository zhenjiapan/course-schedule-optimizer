## 2026-11-22：剪除不可能的课程组件组合并记录 CP-SAT 搜索统计

### 修改动机

课程级教师、星期和时段偏好需要按课程的所有必需组件共同计分。旧实现直接枚举各组件候选班次的笛卡尔积，之后才把每个组合作为评分模式加入模型。若 Lecture 与 Tutorial 等组件之间已有冲突约束，不兼容组合的指示变量必然为 0，却仍会增加建模变量和约束。

另外，API 先前仅返回总耗时和最优性状态，没有记录 CP-SAT 调用数、分支数、冲突数及各求解阶段耗时，难以判断实际瓶颈。

### 修改位置

- `backend/app/optimization/v4/cp.py`
  - 保存已构建的冲突边。
  - 用逐层兼容性检查生成组件组合；发现组合与已选组件冲突时，提前剪去该分支。
  - 记录原始笛卡尔积组合数与实际生成的兼容组合数。
- `backend/app/optimization/v4/solve.py`
  - 为每次 CP-SAT 调用记录阶段、状态、分支数、冲突数和求解器耗时。
  - 返回聚合搜索统计，并标记课程偏好校准、Top-K 排序和同分处理阶段。
- `frontend/features/api.ts`
  - 添加搜索统计的 TypeScript 类型。
- `frontend/features/planner.tsx`
  - 在结果页增加可展开的求解诊断统计。

### 正确性与复杂度影响

- 只有包含现有冲突边的组件组合会被剪除。此类组合在原模型中已被互斥约束禁止，因此不可能对应可行课表；删除其评分模式不会删除任何可行解，也不改变可行课表的评分公式、Top-K 定义或独立检验逻辑。
- 改进主要降低课程评分模式的建模规模。最坏情况仍可能保留完整的笛卡尔积，精确组合优化的最坏情况复杂度没有改变，不能据此宣称多项式时间或固定加速倍数。
- 搜索统计是诊断数据：分支数是 CP-SAT 对多次校准、排序和同分求解的累计值，不等同于“独立课表数量”，也不是唯一搜索节点数。
- 未修改 V4 偏好评分定义，因此本次不改变目标函数版本。

### 验证记录

- 本次按用户要求修改了求解模型、API 返回字段和结果页诊断展示。
- 尚未运行测试、生产构建或真实数据基准；加速幅度和运行环境兼容性仍需验证。

## 2026-11-24：在课表生成期间显示 CP-SAT 分支进度

### 修改动机

原有优化 API 在独立进程中运行，前端只在请求结束后收到结果，无法查看求解进度。用户希望生成课表时实时看到当前分支数。

### 修改位置

- `backend/app/main.py`
  - 为求解进程建立共享进度存储。
  - 新增 `GET /api/v4/progress/{job_id}`，并通过 `X-Progress-Id` 将生成请求与轮询关联。
  - 限制进度记录数量，避免进程内记录持续累积。
- `backend/app/optimization/v4/solve.py`
  - 为 CP-SAT 注册可行解回调，读取分支和冲突计数快照。
  - 记录预处理、模型构建、评分校准、Top-K 排序、同分处理阶段，并跨多个 CP-SAT 子求解累计分支数。
  - 进度上报失败时继续求解，不改变求解结果。
- `frontend/features/api.ts`
  - 增加进度数据类型，并允许 API 请求附带进度 ID。
- `frontend/features/planner.tsx`
  - 生成期间每 500 毫秒轮询一次进度接口，显示阶段、累计分支和冲突数。

### 正确性与统计口径

- 进度数值来自 CP-SAT 找到新解或结束一轮搜索时的快照，页面按最新快照更新；快照之间不会逐个分支回调，因此数字可能跳跃，不能理解为每个分支都被实时推送。
- 页面显示的累计分支数把一次请求中的偏好校准、Top-K 排序和同分求解各阶段的 CP-SAT 分支数相加。
- 进度传输不参与约束、目标函数、超时判定、Top-K 或最优性证明；最终结果仍由原有求解器返回并经独立检验。

### 验证记录

- 确认当前安装的 OR-Tools Python API 存在 `log_callback`、`log_search_progress`、`log_to_stdout` 属性。
- 尚未运行完整求解测试、浏览器验证或多请求压力测试。不同求解实例下的刷新间隔仍需实际验证。

## 2026-11-24：持续搜索与前三名预览

- 网站以后台任务运行无固定时限的 Top-K 搜索，每 10 秒查询进度与前三张已独立检验的候选课表。
- 评分校准完成后，按精确损失与班次顺序保留去重的候选。候选来自 CP-SAT 报告的新解；剪枝和最优性证明仍由求解器完成。
- 保留原有带时限的 API 调用方式。未运行端到端验证。

## 2026-11-24：独立检验器的空档评分保留精确分数

均衡空档的罚分全部触顶时，内置 `min` 可能返回整数，导致后续除法变成浮点数。独立复算改用 Fraction 边界与求和初值，保持与 CP-SAT 编码相同的精确分数。未复跑截图中的完整请求。

### 进度显示

页面每秒读取搜索进度，分开显示已找到的去重课表和搜索分支数。前三张课表仍每 10 秒更新。课表计数只包含求解器报告且已通过独立检验的候选。

### 完整搜索结果统计

前三名证明完成后，在原始硬约束模型上枚举全部不同班次组合。最终显示合格课表总数与各求解阶段累计分支数；未完成枚举时不把部分计数作为总数。
